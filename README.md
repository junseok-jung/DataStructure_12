# 퀵 정렬의 피벗 선택에 따른 성능 비교

## 1. 실험 개요
동일한 무작위 정수 데이터($n = 1,000, 2,000, 4,000, 8,000, 16,000, 20,000$)의 복사본에 대하여 퀵 정렬(Quick Sort)의 세 가지 피벗 선택 방법(**첫 번째 원소, 무작위 원소, 세 원소의 중앙값**)을 적용하고, 정렬 과정에서 발생하는 데이터 간 숫자 비교 횟수를 측정하여 피벗 선택 방식이 분할 균형도와 정렬 성능에 미치는 영향을 분석한다.

## 3. 실험 결과 비교 및 원인 분석

### (1) 데이터 크기 증가에 따른 세 가지 퀵 정렬의 비교 횟수 변화
* **측정 추세:** 데이터 크기 $n$이 $1,000 \rightarrow 2,000 \rightarrow 4,000 \rightarrow 8,000 \rightarrow 16,000$으로 **2배씩 증가할 때마다** 세 가지 피벗 선택 방법 모두 비교 횟수가 단순 2배가 아닌 **약 2.15~2.22배씩 증가**하였다. 또한 $16,000$에서 $20,000$으로 $1.25$배 증가할 때는 비교 횟수가 약 $1.28$배 증가하였다.
* **발생 원인:** 퀵 정렬의 평균 시간 복잡도는 $O(n \log_2 n)$이다. 각 분할 단계(레벨)마다 현재 구간의 원소들을 피벗과 비교하는 연산이 총 $O(n)$번 수행되고, 분할이 반복되는 트리의 깊이가 평균 $O(\log_2 n)$에 비례하므로 데이터 크기 $n$이 2배가 될 때 $\frac{2n \log_2(2n)}{n \log_2 n} = 2 \left(1 + \frac{1}{\log_2 n}\right)$배만큼 비교 횟수가 증가하는 이론적 특성과 정확히 일치한다.

### (2) 첫 번째 원소, 무작위 원소, 세 원소의 중앙값을 피벗으로 선택했을 때의 성능 차이
* **First Element vs Random Pivot:** 모든 데이터 크기에서 두 방식의 비교 횟수는 큰 차이 없이 **거의 유사한 성능**을 보였다 ($n = 20,000$ 기준 `First` 318,142회 vs `Random` 316,580회로 약 0.5% 내외의 미세한 차이).
  * **원인:** 실험에 사용된 원본 배열 자체가 `rand()`를 통해 균일한 난수로 생성되었기 때문에, 구간의 첫 번째 원소(`list[left]`)를 선택하는 것이나 무작위 인덱스의 원소를 선택하는 것이나 확률적으로 동일한 무작위 값을 피벗으로 선택하는 효과를 갖기 때문이다. (단, 입력 데이터가 이미 정렬되어 있거나 역정렬된 상태라면 `First Element` 방식은 매번 최악의 분할이 일어나 $O(n^2)$으로 성능이 급격히 저하되는 반면, `Random Pivot`은 입력 데이터의 정렬 상태와 무관하게 평균 $O(n \log_2 n)$의 성능을 유지한다.)
* **Median-of-Three의 성능 우위:** 세 원소의 중앙값(`Median-of-Three`) 방식은 중앙값을 찾기 위해 매 분할마다 2~3회의 추가 비교 연산을 수행함에도 불구하고, 전 구간에서 `First` 및 `Random`보다 **약 8~9% 적은 비교 횟수**를 기록하며 가장 뛰어난 성능을 보였다 ($n = 20,000$ 기준 `First` 대비 **28,028회 감소**).

### (3) 피벗 선택 방법이 분할 결과와 비교 횟수에 영향을 미치는 이유
* 퀵 정렬에서 비교 연산은 대부분 `partition` 함수 내부에서 구간 내 원소들을 피벗과 비교할 때 발생하며, **전체 비교 횟수는 분할 트리의 깊이(높이)에 의해 결정**된다.
* **편향 분할(Unbalanced Partition)의 문제:** 만약 선택된 피벗이 현재 구간에서 지나치게 작거나 큰 값(극단값)이면, 분할된 왼쪽과 오른쪽 부분 배열의 크기가 $1 : n-2$나 $1 : 9$처럼 한쪽으로 치우치게 된다. 이 경우 큰 쪽 부분 배열의 크기가 거의 줄어들지 않아 분할 단계(재귀 호출 깊이)가 깊어지고, 동일한 원소들이 하위 분할 단계에서 반복적으로 다시 비교되면서 전체 비교 횟수가 크게 증가한다.
* **균등 분할(Balanced Partition)의 효과:** 반대로 피벗이 현재 구간의 실제 중앙값(Median)에 가까울수록 좌우 부분 배열이 이상적인 $5 : 5$ 비율에 가깝게 나뉜다. 이 경우 부분 배열의 크기가 매 단계 절반 수준으로 빠르게 줄어들어 전체 분할 트리의 높이가 최소치인 $\log_2 n$에 수렴하게 되며, 결과적으로 총 비교 횟수가 최소화된다.

### (4) 어떤 피벗 선택 방법이 효과적이었는지 실험 결과를 바탕으로 분석
* 실험 결과 **세 원소의 중앙값 선택(`Median-of-Three`) 방법이 모든 데이터 크기에서 가장 적은 비교 횟수를 기록하여 가장 효과적인 피벗 선택 방법**임을 확인하였다.
* **효과적인 이유:**
  1. **최악의 분할 가능성 차단:** 단일 원소를 뽑는 `First`나 `Random` 방식은 운이 나쁠 경우 구간의 최솟값이나 최댓값을 피벗으로 뽑아 $0 : n-1$의 극단적인 편향 분할을 유발할 수 있다. 반면 `Median-of-Three`는 첫 번째, 중간, 마지막 세 원소 중 중간 크기의 값을 선택하므로, 적어도 **해당 구간의 전체 최솟값이나 최댓값이 피벗으로 선택될 확률을 원천적으로 제거**한다.
  2. **추가 비용 대비 높은 분할 개선 이득:** 세 원소의 중앙값을 판별하기 위해 분할 1회당 2~3회의 비교 횟수가 추가되지만, 이를 통해 피벗이 실제 구간의 중앙값 근처에서 선택될 확률이 높아져 전체 분할 트리의 깊이가 얕아진다. 데이터 크기 $n$이 커질수록 트리 깊이 감소로 절약되는 비교 횟수가 중앙값 탐색에 쓰이는 2~3회의 비용보다 훨씬 커지므로($n = 1,000$에서 7.87% 감소 $\rightarrow n = 20,000$에서 8.81% 감소), 데이터가 많을수록 `Median-of-Three`의 효율성이 더욱 뚜렷해진다.

## 4. [보너스] 재귀적 퀵 정렬과 반복적 퀵 정렬의 성능 비교

### 측정 결과 ($n = 10,000$, Pivot: Median-of-Three, 100회 평균)
```text
Data Size : 10000
Pivot     : Median-of-Three

Recursive Quick Sort : 1.1240 ms
Iterative Quick Sort : 1.0180 ms
```

### 실행시간 차이 및 발생 원인 분석
* **실험 결과:** 동일한 원본 데이터($n = 10,000$)와 동일한 `Median-of-Three` 피벗 선택 및 분할 알고리즘을 적용했을 때, 스택(Stack)을 이용한 **반복적(Iterative) 퀵 정렬이 재귀적(Recursive) 퀵 정렬보다 실행시간이 약 9~10% 더 빠르게 측정**되었다.
* **발생 원인:**
  * 두 방식의 분할 순서와 데이터 간 숫자 비교 횟수는 완전히 동일하지만, **함수 호출 방식의 차이**에서 실행시간 격차가 발생한다.
  * **재귀적(Recursive) 퀵 정렬**은 부분 배열을 분할할 때마다 자기 자신 함수를 반복 호출하므로, 운영체제의 시스템 콜 스택(Call Stack)에 매개변수(`list`, `left`, `right`, `pivot_type`), 복귀 주소(Return Address), 이전 스택 프레임 포인터 등을 저장하고 복원하는 **함수 호출 오버헤드(Function Call Overhead)**가 매번 누적된다.
  * **반복적(Iterative) 퀵 정렬**은 추가적인 함수 호출 없이 단일 `while` 반복문 내부에서 정렬할 구간의 시작과 끝 인덱스(`left`, `right`) 정수 2개만 배열 기반의 명시적 스택에 직접 `push`/`pop`하여 처리하므로, 함수 호출 및 복귀에 따르는 부가 비용이 제거되어 더 빠른 실행 속도를 보인다.
