# 정렬 알고리즘 성능 비교 및 분석 (퀵 정렬 피벗 선택 및 병합 정렬 비교)

## 1. 실험 개요
동일한 무작위 정수 데이터($n = 1,000, 2,000, 4,000, 8,000, 16,000, 20,000$)에 대하여 퀵 정렬의 세 가지 피벗 선택 방법(`First`, `Random`, `Median-of-Three`)과 병합 정렬(Merge Sort), 그리고 재귀적/반복적 퀵 정렬의 **숫자 비교 횟수, 실행시간(ms), 메모리 사용량**을 측정하고 알고리즘의 구조적 특성이 성능에 미치는 영향을 분석한다.

## 3. 항목별 상세 비교 및 원인 분석

### (1) 데이터 크기 증가에 따른 병합 정렬과 퀵 정렬의 비교 횟수 변화
* **비교 횟수 증가 추세:** 데이터 크기 $n$이 2배씩 증가할 때 두 알고리즘 모두 비교 횟수가 단순 2배가 아닌 **약 2.1~2.2배씩 증가**하며, 이는 $O(n \log_2 n)$의 이론적 증가 곡선과 정확히 일치한다.
* **알고리즘 간 비교 횟수 차이:** 모든 데이터 크기 구간에서 **병합 정렬의 비교 횟수가 퀵 정렬보다 적게 측정**되었다 ($n = 20,000$ 기준 병합 정렬 약 26.3만 회 vs 퀵 정렬 Median-3 약 29.0만 회).
* **발생 원인:**
  * **병합 정렬**은 데이터의 분포와 무관하게 매 단계 정확히 **절반($5 : 5$)**으로 분할하므로 분할 트리의 높이가 항상 최소치인 $\lceil \log_2 n \rceil$으로 고정된다.
  * **퀵 정렬**은 선택한 피벗 값에 따라 분할 비율이 $4 : 6$이나 $3 : 7$ 등으로 약간씩 치우칠 수 있어 평균 트리 높이가 $\log_2 n$보다 약 $1.39$배($2 \ln 2 \approx 1.386$) 정도 깊어지기 때문에 데이터 간 비교 횟수 자체는 병합 정렬보다 많이 발생한다.

### (2) 두 정렬 알고리즘의 실행시간 차이
* **측정 결과:** 숫자 비교 횟수는 병합 정렬이 더 적었음에도 불구하고, **실제 실행시간(ms)은 퀵 정렬이 병합 정렬보다 약 30~35% 더 빠르게 측정**되었다.
* **발생 원인:**
  1. **데이터 복사와 이동 오버헤드:** 병합 정렬은 분할된 두 부분 배열을 병합(Merge)할 때마다 임시 배열(`sorted`)에 원소를 모두 기록한 뒤 다시 원본 배열(`list`)로 전체 복사하는 과정을 매 단계마다 반복한다. 반면 퀵 정렬은 피벗을 기준으로 조건에 맞지 않는 두 원소만 제자리에서 교환(`swap`)하므로 데이터 이동 횟수가 훨씬 적다.
  2. **참조 지역성(Cache Locality):** 퀵 정렬의 `partition` 과정은 `low`와 `high` 포인터가 연속된 메모리 공간을 순차적으로 탐색하므로 CPU 캐시 적중률(Cache Hit Ratio)이 매우 높다. 반면 병합 정렬은 원본 배열과 별도의 동적 할당된 임시 배열 사이를 오가며 메모리에 접근하므로 상대적인 메모리 접근 지연이 발생한다.

### (3) 두 정렬 알고리즘의 메모리 사용량 차이
* **측정 결과:** $n = 20,000$ 기준으로 병합 정렬은 **80,000 Bytes(약 78.1 KB)**의 추가 메모리를 사용한 반면, 퀵 정렬은 **약 768 Bytes(1 KB 미만)**만 사용하여 **약 100배 이상의 메모리 사용량 차이**를 보였다.
* **발생 원인:**
  * **병합 정렬**은 비제자리 정렬(Out-of-place Sort) 방식으로, 두 정렬된 구간을 합치기 위해 원본 배열 크기 $n$과 동일한 크기의 보조 배열이 반드시 필요하다.
  * **퀵 정렬**은 추가 배열을 만들지 않고 원본 배열 내부에서 원소 위치만 맞바꾸는 **제자리 정렬(In-place Sort)** 방식으로 동작하며, 재귀 호출 시 분할 구간의 인덱스(`left`, `right`)를 저장하는 시스템 콜 스택(또는 명시적 스택) 공간만 사용한다.

### (4) 퀵 정렬의 피벗 선택 방법에 따른 성능 차이
* **성능 순서:** 비교 횟수가 적은(성능이 우수한) 순서는 **`Median-of-Three` (최소) -> `Random` -> `First`** 순으로 나타났다. ($n = 20,000$ 기준 `Median-of-Three`는 `First` 대비 약 28,000회, 비율로는 **약 8.8%의 비교 횟수 감소** 효과를 보였다.)
* **피벗 선택이 분할 결과와 비교 횟수에 영향을 미치는 이유:**
  * **First vs Random:** 실험에 사용된 원본 데이터가 이미 난수(`rand()`)로 무작위 생성되었기 때문에 첫 번째 원소를 선택하는 것과 무작위 위치의 원소를 선택하는 것은 확률적으로 동일한 분할 균형도를 보인다. (단, 이미 정렬되거나 역정렬된 데이터가 입력될 경우 `First`는 매번 $1 : n-1$의 최악 분할이 발생해 $O(n^2)$으로 성능이 급락하지만, `Random`은 이를 예방한다.)
  * **Median-of-Three의 우수성:** 구간의 첫 번째, 중간, 마지막 세 원소 중 중앙값을 피벗으로 선택하면, 최소한 해당 구간에서 **가장 작은 값이나 가장 큰 값(극단값)이 피벗으로 선택될 확률이 제거**된다. 결과적으로 좌우 부분 배열이 $5 : 5$에 훨씬 가깝게 균등 분할되어 재귀 트리의 깊이가 낮아지며, 중앙값을 구하기 위해 추가되는 비교(분할당 2~3회)를 감안하더라도 전체 비교 횟수가 가장 적게 나타난다.

### (5) 병합 정렬과 퀵 정렬의 시간 복잡도 및 공간 복잡도 차이

| 구분 | 병합 정렬 (Merge Sort) | 퀵 정렬 (Quick Sort - First) | 퀵 정렬 (Random / Median-3) |
| :---: | :---: | :---: | :---: |
| **최선 시간 복잡도** | $O(n \log_2 n)$ | $O(n \log_2 n)$ | $O(n \log_2 n)$ |
| **평균 시간 복잡도** | $O(n \log_2 n)$ | $O(n \log_2 n)$ | $O(n \log_2 n)$ |
| **최악 시간 복잡도** | $O(n \log_2 n)$ | $O(n^2)$ (정렬된 입력 시) | $O(n^2)$ (확률적으로 거의 발생 안 함) |
| **공간 복잡도** | $O(n)$ (임시 배열 필수) | 평균 $O(\log_2 n)$, 최악 $O(n)$ | $O(\log_2 n)$ (재귀 스택 깊이) |
| **안정성 (Stability)** | 안정 정렬 (Stable) | 불안정 정렬 (Unstable) | 불안정 정렬 (Unstable) |

### (6) 메모리 사용량의 측정 방법과 계산 기준
* **계산 기준:** 원본 데이터를 저장하는 기본 배열(`sizeof(int) * n`)은 두 정렬 알고리즘에 공통으로 요구되는 입력 공간이므로 제외하고, **정렬 알고리즘이 실행되는 동안 추가로 점유하는 최대 보조 메모리(Peak Auxiliary Memory)**를 기준으로 측정하였다.
* **측정 방법:**
  1. **병합 정렬:** 병합 함수를 위해 동적 할당한 임시 배열 `sorted`의 크기를 기준으로 `n * sizeof(int)` (즉, $4n\text{ Bytes}$)로 계산하였다.
  2. **퀵 정렬:** 재귀 호출 시 현재 호출 깊이(`curr_depth`)를 추적하여 정렬 중 도달한 **최대 재귀 깊이(`max_depth`)**를 기록한 뒤, 호출 1회당 스택 프레임 크기(매개변수 및 복귀 주소 포함 약 `32 Bytes`, 또는 반복적 퀵 정렬의 경우 스택에 동시에 쌓인 최대 정수 개수 $\times 4\text{ Bytes}$)를 곱하여 산출하였다.
